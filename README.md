## 1. Структура проєкту
- `include/` — заголовні файли класу `LinearSystem`, ієрархії винятків та допоміжного класу `ScopeLogger`.
- `src/` — реалізація методів розв'язання СЛАР методом Гауса з вибором головного елемента.
- `demo/` — демонстрація поширення винятків, повторного генерування (`throw;`) та розкручування стека (RAII).
- `antipattern/` — демонстрація проблем при використанні винятків примітивних типів (`int`, `std::string`) та object slicing.
- `tests/` — модульні тести на базі фреймворку Google Test.

## 2. Інваріанти класу `LinearSystem`
1. Розмірність системи n > 0.
2. Матриця коефіцієнтів A є квадратною і містить рівно n х n елементів.
3. Вектор вільних членів b містить рівно n елементів.
4. Усі елементи матриці та вектора є скінченними дійсними числами (не `NaN` і не `Inf`).

## 3. Ієрархія винятків
- `LinearSystemException` (похідний від `std::runtime_error`) — базовий клас винятків бібліотеки.
  - `SingularMatrixException` — генерується, якщо матриця вироджена.
  - `InvalidSizeException` — генерується при невідповідності розмірів вектора b або вектора наближення x розмірності n.
  - `InvalidDataException` — генерується при виявленні значень `NaN` або `Inf`.
- Для базових порушень контракту використовується стандартний виняток `std::invalid_argument`.

## 4. Гарантії безпеки винятків
-RAII: Внутрішні дані зберігаються у контейнерах `std::vector<double>`, що гарантує автоматичне звільнення пам'яті під час розкручування стека без витоків.
-Сильна гарантія: Реалізована в методі `updateSystem()` за патерном *prepare-then-commit* — спочатку виконується валідація та копіювання у тимчасові вектори, і лише після цього відбувається обмін даних через `swap()`, що не генерує винятків. У разі помилки попередній стан системи залишається незмінним.

## 5. Висновки щодо антипатернів
Кидання примітивних типів (`throw 404;` або `throw std::string(...)`) порушує єдину ієрархію обробки помилок: стандартний перехоплювач `catch (const std::exception&)` їх ігнорує. Також повторне генерування через `throw ex;` замість `throw;` призводить до object slicing, тобто втрати інформації похідного класу винятку.
